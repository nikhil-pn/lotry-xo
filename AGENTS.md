# Lotry on XO: notes for AI agents

Start with `README.md`, then `CONTEXT.md` (use its terms), then `src/lotry-template.mjs`.

## What this is

A lottery round on Bitcoin Cash, written as one XO wallet template. The pot is a P2SH32 covenant with no signature path;
its minting NFT commitment is the round's state. Tickets are immutable CashTokens NFTs. Chipnet (testnet) only.

## Commands

```bash
npm install --ignore-scripts   # a native SQLite add-on deep in the XO deps fails to compile; nothing uses it
npm test             # 61 tests, no network: covenant paths and attacks in libauth's BCH 2026 VM, plus sandbox rounds
npm run build:play   # rebuilds web/play.js from web-src/play.mjs (commit both)
node scripts/lotry.mjs status            # reads a round from Chipnet (network)
```

Node 24 is required (`engines` in package.json). On Node 18 the tests fail.

## Where things are

- `src/lotry-template.mjs`: the template. Changing any script or variable changes the template identifier, and the
  committed invitations in `rounds/` stop matching it. Don't change it unless asked; if you must, regenerate
  `templates/lotry.json` (`node scripts/export-template.mjs`) and say that the proof rounds use the old identifier.
- `src/round-state.mjs`: commitment formulas, compiled from the template's own scripts.
- `src/chain-time.mjs`: lock heights. Since Faster Blocks, a lock height on chipnet counts 10-minute chunks, not blocks.
- `scripts/lotry.mjs`: the CLI. One XO engine per process, so each wallet runs as its own process.
- `web/`: the static website, deployed by Vercel from `web/` on every push to `main`.
- `docs/PROOF.md`: generated by `node scripts/export-proof.mjs`; don't edit by hand.

## Rules

- Never commit secrets. Wallet mnemonics live outside the repo (`LOTRY_ENV`, default `~/.config/pi/lotry-xo.env`);
  engine state lives in `state*/`, which is git-ignored.
- Every new covenant rule needs a test that shows the attack is refused by the covenant itself, not by the test harness.
- Pot-spending transactions pay an explicit fee: the engine's estimate does not count the redeem script.
- Keep claims in README and on the site true to the chain: link a transaction for anything you say happened.
- `FEEDBACK.md` is written by Nikhil personally. Don't edit its wording.
