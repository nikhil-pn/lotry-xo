The Story of Lotry

In 2025 we built Lotry.fun on Base at Base Batch India, a runner-up; it now runs on Solana. Tickets traded on a bonding curve and Chainlink VRF picked the winner.

But the pot sat in a contract with an owner, and the owner triggered the payout. Players had to trust that key.

On Bitcoin Cash a coin can carry its own rules. For BLAZE we moved the core round there as a fixed-price raffle, not the bonding-curve market: the pot is a coin with no key, and the chain checks the draw, the payout and every refund.

Benefits of Lotry on XO

  • The organiser can never touch the pot
    • no key, no admin path, no signature check at all
  • Tickets are real NFTs you hold
    • numbered CashTokens in the player's own wallet
  • The winner is checked by the chain
    • the covenant computes sha256(secret) mod tickets + 1
  • Refunds if the organiser vanishes
    • after the refund height if never drawn, or the claim deadline if unclaimed
  • Sub-cent fees on Bitcoin Cash
  • One reviewable template
    • every rule in one file; 60 tests, 41 attacks refused

BCH Usage

Every rule of the round runs in Bitcoin Cash script. Nothing off chain holds the money.

CashTokens: genesis + a minting NFT as state

Opening a round creates its own token category. The pot's minting NFT commitment is the round: ticket count, closed, then the winner.

Covenant introspection

The pot checks its next self: same script, same category, value + price, count + 1, one immutable ticket out (OP_OUTPUTVALUE, OP_UTXOTOKENCOMMITMENT).

OP_CHECKLOCKTIMEVERIFY, after Faster Blocks

After the draw height anyone closes sales, before any reveal; refunds wait for their deadlines. Lock heights now advance once every ten 1-minute blocks; we measured Chipnet's activation: block 332,451.

XO invitations, two parties

A sale is one transaction: the organiser adds the pot, the player adds coins and takes the ticket, each signs their own part.

The draw path of the pot covenant: closed pots only

OP_DUP OP_SHA256 <secretHash> OP_EQUALVERIFY
OP_0 OP_UTXOTOKENCOMMITMENT OP_4 OP_SPLIT <0xc1> OP_EQUALVERIFY
OP_BIN2NUM OP_DUP OP_0 OP_GREATERTHAN OP_VERIFY // ≥ 1 ticket
OP_SWAP OP_SHA256 <4> OP_SPLIT OP_DROP
<0x00> OP_CAT OP_BIN2NUM
OP_SWAP OP_MOD OP_1ADD        // winner
OP_4 OP_NUM2BIN <0xd0> OP_CAT
OP_0 OP_OUTPUTTOKENCOMMITMENT OP_EQUALVERIFY
potCarriesOn                 // same script + NFT
OP_0 OP_OUTPUTVALUE OP_0 OP_UTXOVALUE
OP_NUMEQUALVERIFY            // keeps every sat
