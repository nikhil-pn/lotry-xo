01 · How a round works

A coin with no key.

On Bitcoin Cash, money sits in coins, and every coin carries a small script that says how it may be spent. Most scripts ask for a signature from one key. The pot's script asks for none. It only lists the next moves it allows: one more ticket sold, sales closed, the right winner written down, the winner paid, or a ticket refunded after a deadline.

No key means nothing to lose, leak, or run away with. The organiser runs the round but can never move the pot. What it does hold is the secret that picks the winner; the limits below say what that allows.

  1. 1

    Open

    Organiser

    Creates the pot: a fresh coin carrying the round's minting NFT. It also publishes the hash of a secret it will reveal at the draw.

    pot 0 tickets

  2. 2

    Buy a ticket

    Organiser and player, together

    One transaction, two people. The organiser adds the pot, the player adds the price and receives ticket #n, a numbered NFT nobody can change.

    pot n tickets, + price

  3. 3

    Close

    Anyone, after the draw height

    Sales stop and the ticket count is frozen, before any secret is revealed. Value and NFT stay as they are.

    pot closed at n

  4. 4

    Draw

    Organiser, on a closed pot

    The organiser reveals the secret. The covenant checks it against the hash and works out the winner itself: sha256(secret) mod tickets + 1. It refuses a pot that is not closed.

    pot winner #k

  5. 5

    Claim

    Whoever holds the winning ticket

    The winner spends the ticket together with the pot. Both NFTs are burned and the whole pot is paid out.

    pot paid to the winner

  6. 6

    or, if no claim

    Refund

    Any ticket holder, after a deadline

    After the refund height if the round was never drawn, or after the claim deadline if it was drawn but nobody claimed. Each ticket burns for its price back; nobody has to say yes. The first refund ends the round: no draw or claim after it.

    pot refunds only

The pot's state is its NFT commitment: a 4-byte ticket count while the round is open; the count plus 0xc1 once sales close; the winning number plus 0xd0 once drawn; or the 4 bytes plus 0xee once refunds begin. The covenant checks every move against it.

03 · Migrated from Lotry.fun

Its core round, no owner.

Lotry.fun is our lottery: built on Base for Base Batch India 2025, where it was runner-up, and now running on Solana. There, tickets trade on a bonding curve. For BLAZE we did not port that market. We moved the core round, the part where money waits for a winner, to Bitcoin Cash as a fixed-price raffle round. The Solidity code was the spec; everything here was written during BLAZE.

Lotry.fun · Base · Solidity Lotry on XO · Bitcoin Cash
Sales A bonding-curve ticket market: the price moves with every buy, and tickets can be sold back A fixed-price raffle round: every ticket costs the price set at open. Not a port of the bonding curve
Ticket An ERC-20 token from LotryTicket.sol An immutable CashToken NFT, numbered by the pot and held in the player's own wallet
Pot Held by a contract with an owner One coin locked to a covenant with no key at all
Randomness Chainlink VRF (RandomWalletPicker.sol) Commit-reveal: the secret's hash is fixed at open, and the covenant checks the reveal and computes the winner
Payout The owner calls distributeRewards(winner) The winner claims by burning the winning ticket together with the pot
If no draw No refund if the draw never comes; tickets can only be sold back on the bonding curve Tickets refundable after the refund height; if drawn but never claimed, after the claim deadline

04 · Why XO

The whole app, one template.

XO is General Protocols' template stack for Bitcoin Cash: a wallet loads a template and knows every action it offers, who takes part, and what each transaction must look like.

i.

One reviewable file

Roles, actions, transactions and the covenant itself live in lotry-template.mjs (as XO JSON: lotry.json). Read one file and you know every way the money can move.

ii.

Invitations: each side adds its part

A ticket sale is one transaction built by two people. The organiser starts an invitation with the pot; the player joins, adds coins, receives the ticket and signs. Each signs only their own inputs.

iii.

Follow-up actions

Coins know what can happen next. The pot offers the next sale and the draw to the organiser; a ticket offers claim and refund to whoever holds it, with no custom wallet code.

05 · Limits

Stated plainly.

No key can spend the pot, and it only ever pays the winning ticket or refunds tickets. Here is what that does not cover, so nobody has to find out the hard way.

  • The organiser knows the secret.

    So an organiser who buys tickets before sales close could steer which ticket wins, like any raffle host who also plays. It could also refuse to reveal, and the round falls back to refunds. Either way it can never take the pot. Next: buyer-supplied randomness, so no one party picks the winner.

  • Some coins stay behind.

    When a round ends, its 2,000-sat seed and the pot NFT stay in the covenant; no path pays them out. A round with zero tickets can be closed, but never drawn or refunded.

  • Check the heights before you buy.

    The template does not force the draw, refund and claim heights into order. Our rounds always use draw, then refunds, then the claim deadline, with time in between. A buyer should check the three heights in the round's open invitation before paying.

  • Chipnet only.

    Every transaction on this page uses test coins on Chipnet, the Bitcoin Cash test network. Nothing here is real money yet.

  • Tickets are bought from a CLI.

    Today a sale runs from the command line: the organiser and the player each run their own step. There is no browser wallet flow yet.

Found while building

Faster Blocks changed what a lock height means on Chipnet.

Chipnet switched to 1-minute blocks on 15 Nov 2026 (CHIP-2025-03, Faster Blocks). Lock-time heights kept their 10-minute meaning, so a lock height now advances once every ten blocks. We measured the activation height on the live network: at block 341,561 Chipnet accepted nLockTime 333,361 and refused 333,362, which puts activation at block 332,451.

The round's draw and refund heights use this rule (src/chain-time.mjs). Anyone using OP_CHECKLOCKTIMEVERIFY on Chipnet needs it today; mainnet follows on 15 May 2027.

Blocks, 1 minute each

Lock height, still 10 minutes

lock height = 332,451 + floor((block − 332,451) / 10)

06 · Try it

Run it yourself.

Node 24. Chipnet coins are free from the on-chain faucet contracts (scripts/faucet-contract.mjs). Or run nothing at all: import templates/lotry.json (the template both live rounds use) into blaze.xo.cash and open any invitation file from Round A. Or play a round in the browser at /play.html.

git clone https://github.com/nikhil-pn/lotry-xo && cd lotry-xo
npm install --ignore-scripts
npm test                                             # 61 tests: every covenant path, 41 attacks refused, BCH 2026 VM

node scripts/make-wallets.mjs                        # organiser + two buyers, mnemonics kept outside the repo
node scripts/addresses.mjs BUYER_A                   # a wallet's Chipnet address
node scripts/faucet-contract.mjs <bchtest:address>   # free test coins

node scripts/lotry.mjs open                          # organiser opens a round
node scripts/lotry.mjs offer                         # organiser starts a ticket sale invitation
node scripts/lotry.mjs take BUYER_A                  # player adds coins, takes the ticket, signs
node scripts/lotry.mjs seal                          # organiser adds the pot's unlocking script and broadcasts
node scripts/lotry.mjs close                         # after the draw lock height (anyone may): sales stop
node scripts/lotry.mjs draw                          # organiser reveals the secret on the closed pot
node scripts/lotry.mjs claim BUYER_A                 # the winning ticket takes the pot
node scripts/lotry.mjs refund BUYER_B                # never drawn, or drawn and unclaimed by the deadline
node scripts/lotry.mjs status                        # the pot as the organiser sees it
